# E820. BIOS routine to get info about which parts of physical memory are usable RAM, and which parts are reserved


BIOS answers with:

```text
Region 1:
start = 0 KB
size  = 639 KB
type  = usable

Region 2:
start = 639 KB
size  = 385 KB
type  = reserved

Region 3:
start = 1 MB
size  = 127 MB
type  = usable
```

That collection of regions is the **memory map**.

---

## Step 1 — BIOS gives us one region at a time

This is the biggest thing to understand.

BIOS does NOT give us the whole map at once.

We do:

```text
ask BIOS
↓
get region #1

ask BIOS again
↓
get region #2

ask BIOS again
↓
get region #3

...
```

Eventually BIOS says:

```text
that's the last one
```

That's E820.

---

## Step 2 — Where does BIOS put each region?

We tell BIOS:

> “Write your answer into RAM here.”

We want to start storing our map at:

```text
112 KB
```

So the first region goes at:

```text
112 KB
```

The second one goes immediately after it.

Each region record is **20 bytes**.

So:

```text
112 KB
│
├── entry 0      20 bytes
├── entry 1      20 bytes
├── entry 2      20 bytes
├── entry 3      20 bytes
...
```

Very simple.

---

# Step 3 — What is inside one 20-byte entry?

Exactly three things:

```text
8 bytes   WHERE the region starts
8 bytes   HOW LARGE the region is
4 bytes   WHAT TYPE of memory it is
```

So:

```text
+0   start address   8 bytes
+8   length          8 bytes
+16  type            4 bytes
```

Example:

```text
start  = 1 MB
length = 127 MB
type   = 1
```

means:

> From 1 MB onward, there are 127 MB of usable RAM.

For us, the most important type is:

```text
type 1 = usable RAM
```

Everything else can later be treated as:

```text
don't allocate from it
```

---

# Step 4 — How do we ask BIOS?

We prepare some registers.

Think of them like arguments to a function.

We put:

```text
EAX = 0xE820
```

Meaning:

> I want the E820 memory-map function.

Then:

```text
EDX = 0x534D4150
```

That's just a required magic value.

Think:

```text
"yes, I really mean the memory-map function"
```

Then:

```text
ECX = 20
```

Meaning:

> My buffer can hold one 20-byte entry.

Then:

```text
EBX = 0
```

Meaning:

> Give me the first entry.

And finally:

```text
ES:DI = where in RAM BIOS should write the entry
```

For us:

```text
ES:DI → 112 KB
```

Then we do:

```asm
int 0x15
```

And BIOS writes one entry into RAM.

---

# Step 5 — What happens after the call?

After:

```asm
int 0x15
```

two things matter.

First:

```text
RAM at 112 KB
```

now contains:

```text
start
length
type
```

Second:

```text
EBX
```

now contains a value BIOS gives us.

That value means:

> “Use this next time to get the next entry.”

So:

```text
first call:
EBX = 0
```

BIOS gives entry #1 and returns some new EBX.

Then:

```text
second call:
use the EBX BIOS gave us
```

BIOS gives entry #2.

Then again.

---

# Step 6 — How do we know when to stop?

Eventually BIOS returns:

```text
EBX = 0
```

That means:

> The entry I just gave you was the last one.

So the logic is simply:

```text
EBX = 0

ask BIOS
↓
save entry

EBX = 0?
  yes → done
  no  → ask again
```

That's really the whole thing.

---

# Step 7 — What does ES:DI mean again?

Because we're still in real mode, BIOS wants a real-mode pointer.

You want:

```text
112 KB = 0x1C000
```

Real-mode physical address is:

```text
ES × 16 + DI
```

So:

```text
ES = 0x1C00
DI = 0
```

gives:

```text
0x1C00 × 16
= 0x1C000
= 112 KB
```

So:

```text
ES:DI = 1C00:0000
```

means:

> Write the E820 entry at physical RAM address 112 KB.

---

# The entire thing in one picture

```text
WE PREPARE:

EAX = E820
EDX = magic "SMAP"
ECX = 20
EBX = 0
ES:DI = 112 KB

        ↓

     int 0x15

        ↓

BIOS WRITES:

112 KB
┌──────────────────────┐
│ start address  8 B   │
│ length         8 B   │
│ type           4 B   │
└──────────────────────┘

and BIOS gives us:

EBX = "use this to get next entry"
```

Then:

```text
move destination forward by 20 bytes
call BIOS again
```

Repeat until:

```text
EBX = 0
```

Done.
